# OGSR Engine 3.597 (X64) WoT&SP Fixes

Основа: чистая `OGSR/OGSR-Engine:main_cop_cs`, коммит `9d0021ce63249bacbc8294ea7ae51e8571848c87`. Сборка `Release | x64`.

## Четыре правки

1. **Русские названия звуковых устройств.** Unicode-шрифт назначается списку и выбранному значению. Исходные строки и токены OpenAL сохранены без перекодирования. Размер шрифта 18 устраняет смещение текста в поле CoP.
2. **Подсветка обвесов WoT/Shoker.** Проверяются `mod_addons_list` и точные имена секций в `scopes`/`magazines`. Подсветка работает в обе стороны. Штатная проверка обычных обвесов сохранена, установка остаётся задачей оружейных скриптов мода.
3. **Физические защиты артефактов.** Карточка показывает ненулевые `strike_immunity`, `wound_immunity`, `explosion_immunity`, `fire_wound_immunity` из `hit_absorbation_sect`, если предусмотрены строки XML. Расчёт защиты не меняется.

4. **Сохранение состояния машин, включая БТР.** В `CSE_ALifeCar::load()` читается хвост пакета, который записывает `CCar::SaveNetState()`: позиция, углы, состояния дверей и колёс, здоровье. Физические кости по-прежнему синхронизируются штатным способом. Формат записи сохранений не меняется.

Правки 2–3 перенесены из `DarknessSpectre/OGSR-Engine-WoT-SP-Fixes`, коммит `ae90aac38335c4fb6bce1a9fe58b47d1ea55f378`. Полная сторонняя ветка не используется. Правка 4 перенесена точечно из `DarknessSpectre/OGSR-Engine-WoT-SP-Fixes`, коммит `1429726592ad92a0f5f8887d22c8b7d57ee589e5`, файл `ogsr_engine/xrServerEntities/xrServer_Objects_ALife.cpp`. Она применяется ко всем объектам `CSE_ALifeCar`, а не только к одному сюжетному БТР.

Версия в игре и строковых свойствах EXE: **3.597 (X64) WoT&SP Fixes**. Числовая версия Windows: `3.597.0.0`.

## Установка

Для чистого «Зова Припяти» 1.6.02 используются `bin_x64` и `gamedata` из архива. Ресурсы самой игры нужны отдельно: архив движка не является полной игрой.

**Поверх SP, WoT и других модов объединяйте конфиги с файлами мода.** Полная замена модифицированных `external.ltx`, XML настроек или `af_params` базовыми файлами может убрать настройки и оформление мода. Для карточки артефактов достаточно перенести четыре новых узла в существующие `af_params`.

В архив включён x64 `vcomp140.dll`, необходимый этому EXE через штатный DirectXTex/OpenMP. Он размещается рядом с `xrEngine.exe`. Сохранения из-за этих UI-правок начинать заново не требуется.

### Переход со скриптового обхода БТР

Если ранее установлен `SP-OGSR_BTR_script_fix.zip`, перед проверкой новой нативной сборки верните оригинальные `gamedata/scripts/city_btr_scene.script` и `gamedata/scripts/bind_stalker.script` из `SP-OGSR_BTR_script_fix_rollback.zip`. Скриптовый обход отдельно хранит здоровье и может подменять состояние уже после штатной загрузки; для проверки исправления движка он не нужен. Это рекомендация по установке: архив движка не содержит полных модовых скриптов и не заменяет их автоматически.

Формат записи совместим с прежней сборкой. Урон, который уже был потерян в старом сохранении, восстановить невозможно: после установки исправленного движка нужно создать новое сохранение с нужным состоянием машины. Для проверки лучше взять сохранение до установки скриптового обхода. Если обход уже удалил объект и это записано в сохранении, замена движка или скриптов сама по себе его не вернёт.

Чтение состояний дверей и колёс исправлено, но их физическое восстановление в `CCar::RestoreNetState()` остаётся отключённым в базовом OGSR. Данная правка не включает его заново.


## Повторная сборка

Нужны Git, Visual Studio 2022/2026 с Desktop C++ и Windows SDK. Используйте короткий путь, например `C:\src\ogsr3597`, либо временный диск `subst`: имена файлов FidelityFX длинные.

```powershell
powershell -ExecutionPolicy Bypass -File .\Restore_Build_3.597_Dependencies.ps1
powershell -ExecutionPolicy Bypass -File .\Build_3.597_x64.ps1
```

Первый скрипт получает точные коммиты зависимостей из `Build_3.597_dependencies.json`. Второй полностью пересобирает `Engine.sln`, `Release | x64`, и задаёт:

```text
APPVEYOR_BUILD_VERSION=3.597
APPVEYOR_REPO_NAME=WoT&SP Fixes
CONFIGURATION_GA=Release
```

Результат находится в `bin_x64`. После успеха скрипт копирует туда x64 `vcomp140.dll` из Visual Studio Redistributable. Исходный `Update_Components.cmd` сохранён, но может загрузить другие версии плавающих зависимостей.
